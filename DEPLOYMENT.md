# Deploying RetailPulse AI

The app ships as **one Docker image**: Express serves the API under `/api` and the built React app on the same origin, so there is no CORS setup and only one service to run. The database is PostgreSQL with the `pgvector` extension.

The steps below use two free tiers:

| Part | Service | Why |
|---|---|---|
| Database | [Neon](https://neon.tech) | Free PostgreSQL that supports `pgvector`, with no expiry |
| App | [Render](https://render.com) web service (Docker) | Builds the `Dockerfile` from GitHub and redeploys on every push to `main` |

Any host that runs a Docker image and any PostgreSQL 16+ database with `pgvector` will also work.

## What you need

- The GitHub repository with this code
- A Groq API key ([console.groq.com/keys](https://console.groq.com/keys))
- Node.js 22.22+ on your laptop, for the one-time database setup

## 1. Create the database (Neon)

1. Sign up at Neon and create a project, using a region near you (for India, `ap-southeast-1` Singapore).
2. Copy the connection string from **Connection details**. It looks like:
   ```
   postgresql://USER:PASSWORD@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
   If it ends with `&channel_binding=require`, remove that part.

## 2. Load the schema and demo data (from your laptop, once)

In a terminal in `backend/`, set the Neon connection string and a demo password for this shell session. Exported variables take priority over your local `backend/.env`, which is left unchanged:

```bash
export DATABASE_URL='postgresql://…neon.tech/neondb?sslmode=require' SEED_DEMO_PASSWORD='choose-a-demo-password'
```

Then create the tables, load the demo data, and embed the policy documents:

```bash
npm run db:deploy && npm run db:seed && npm run kb:ingest
```

- `db:deploy` creates the tables and the `vector` extension.
- `db:seed` loads the 4 stores, 50 products and the demo accounts, which all use your `SEED_DEMO_PASSWORD`.
- `kb:ingest` embeds the 6 policy documents (41 sections) into pgvector.

Close the terminal afterwards, or run `unset DATABASE_URL SEED_DEMO_PASSWORD`, so later commands use your local database again.

## 3. Deploy the app (Render)

1. Sign up at Render with GitHub.
2. Click **New → Blueprint**, pick the repository, and Render reads `render.yaml`.
3. When asked, fill in the values marked "sync: false":
   - `DATABASE_URL`: the Neon connection string
   - `GROQ_API_KEY`: your Groq key
   - `ADMIN_EMAILS`: your own email address
4. Click **Apply**. The first build takes a few minutes, because it installs dependencies, builds the frontend and downloads the embedding model into the image.

`JWT_SECRET` is generated by Render. `DEMO_LOGIN_ENABLED=true` starts the site with the one-click demo buttons on.

When it's live, open `https://<your-service>.onrender.com`.

## 4. Check it

```bash
curl https://<your-service>.onrender.com/api/health
```
```bash
curl https://<your-service>.onrender.com/api/health/ai
```

Both should return `200`. Then:

1. On the sign-in page, choose **Create account** and sign up with the email you put in `ADMIN_EMAILS`. You are now an admin.
2. Open **Admin** in the operations header. From there you can switch demo access and sign-ups on or off and change anyone's role or tier, with no code changes or redeploys.

If your email account already existed before you added it to `ADMIN_EMAILS`, just sign in again and it becomes an admin.

**Re-seeding wipes accounts:** `npm run db:seed` empties every table, including users. After a re-seed, sign up again with your admin email.

## How the container starts

`npm run start:prod` runs `prisma migrate deploy` (it applies new migrations and is safe to repeat), then starts the server. Adding a migration later only needs a push: the next deploy applies it.

## Things to know

- **Cold starts:** Render's free tier sleeps after 15 minutes without traffic. The first request after that takes about a minute.
- **Memory:** the container uses about 200 MB after loading the embedding model, within the free tier's 512 MB.
- **Demo data:** the 14-day sales history is relative to the day you seed. Re-run `npm run db:seed` (step 2) to refresh the inventory numbers. This also resets orders and tickets.
- **Groq limits:** the free Groq tier limits requests per minute. The app also limits each user to 10 AI requests a minute, and the demo accounts are shared by every visitor.
- **Secrets:** never commit `.env` files. Keys live only in the Render dashboard and your local env files.

## Run the production image locally

```bash
docker build -t retailpulse .
```
```bash
docker run -p 4100:4000 --env-file backend/.env.production retailpulse
```

`backend/.env.production` is a file you create with `DATABASE_URL`, `JWT_SECRET`, `GROQ_API_KEY`, `ADMIN_EMAILS` and `DEMO_LOGIN_ENABLED`. It is git-ignored like every `.env.*` file. Then open http://localhost:4100. To use your local Docker database instead of Neon, set `DATABASE_URL` to `postgresql://postgres:postgres@host.docker.internal:5432/<database>`.
